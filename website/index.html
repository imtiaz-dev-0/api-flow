api.ts — Universal Setup
TypeScript 5.0+
import { createApi } from 'api-flow-client'

// 1. Single powerful client instance
export const api = createApi({
  baseURL: 'https://api.example.com/v1',

  // Mutex auth refresh — queues concurrent 401s automatically
  auth: {
    getAccessToken: () => localStorage.getItem('token'),
    refresh: async (refreshToken) => {
      const res = await fetch('/auth/refresh', { method: 'POST' })
      const { token } = await res.json()
      return token
    }
  },

  // In-memory LRU cache + TTL expiration
  cache: { enabled: true, ttl: 300_000 },

  // Exponential retry with randomized jitter
  retry: { attempts: 3, jitter: true }
})

// 2. Fully typed & deduped requests
const users = await api.get<User[]>('/users')
console.log(users.data, users.duration)

Built for Modern Apps. No Extra Libraries Needed.

Say goodbye to pasting custom 401 interceptors, retry loops, and cache maps into every new project.

Auth & Token Refresh Mutex

When 5 requests hit a 401 expired token at once, api-flow halts them, executes exactly one refresh call, and replays all 5 requests automatically with the new token. Zero race conditions.

No Thundering Herd

Smart Memory LRU Cache

Zero-config in-memory caching with TTL expiration, in-flight request deduplication, and regex pattern invalidation via api.invalidateCachePattern().

import { createApi } from 'api-flow-client'

const api = createApi({
  baseURL: 'https://api.example.com',
  auth: {
    // Injects "Authorization: Bearer <token>" automatically
    getAccessToken: () => localStorage.getItem('access_token'),
    getRefreshToken: () => localStorage.getItem('refresh_token'),
    
    // Called ONCE when any request receives 401
    refresh: async (refreshToken) => {
      const response = await fetch('https://api.example.com/auth/refresh', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ refreshToken })
      })
      const data = await response.json()
      localStorage.setItem('access_token', data.accessToken)
      return data.accessToken
    }
  }
})

import React from 'react'
import { api } from './api'
import { useGet, usePost, useDelete } from 'api-flow-client/hooks'

export function UserProfile() {
  // Auto-fetches on mount, cancels on unmount
  const { data, loading, error, refetch } = useGet<User>(api, '/profile')

  // Mutation hooks for updates
  const { mutate: updateProfile, loading: saving } = usePost(api, '/profile')
  const { mutate: deleteAccount } = useDelete(api, '/profile')

  if (loading) return <div>Loading user profile...</div>
  if (error) return <div>Error: {error.message}</div>

  return (
    <div>
      <h1>{data?.name}</h1>
      <button onClick={() => updateProfile({ name: 'New Name' })}>Update</button>
      <button onClick={() => refetch()}>Refresh</button>
    </div>
  )
}
// app/users/page.tsx (Next.js App Router / SSR)
import { createServerSideApi, extractServerHeaders } from 'api-flow-client'
import { headers } from 'next/headers'

export default async function UsersPage() {
  const incomingHeaders = await headers()
  
  // Forwards auth cookies & IP transparently
  const api = createServerSideApi({
    baseURL: process.env.INTERNAL_API_URL,
    headers: extractServerHeaders({ headers: incomingHeaders })
  })

  const response = await api.get<User[]>('/users')

  return (
    <main>
      <h1>Server-Rendered Users ({response.data.length})</h1>
    </main>
  )
}

Frequently Asked Questions

Common Questions

Is api-flow-client truly zero dependencies?

Yes! In default mode, api-flow-client has zero runtime dependencies. It uses the platform's native fetch and AbortController, which are standard in modern browsers, Node.js 18+, Bun, Deno, and React Native. Axios is only an optional peer dependency if you explicitly want to use the Axios adapter.

How does the 401 token refresh mutex work?

When multiple concurrent API calls receive a 401 Unauthorized status, standard clients fire multiple simultaneous refresh token requests (which can cause invalidation race conditions). api-flow-client utilizes an internal mutex queue: the first request triggers your auth.refresh() callback while subsequent failing requests are parked in a promise queue. Once the new token arrives, all queued requests are automatically re-executed with the new authorization header.

Can I use api-flow-client in Next.js Server Components?

Absolutely. api-flow-client exports createServerSideApi and extractServerHeaders, specifically designed for Next.js App Router (Server Components & Server Actions) and Pages Router. It automatically extracts incoming cookies, client IPs, and auth tokens from headers and forwards them without browser-only APIs.

How do I install the React hooks?

The React hooks are bundled inside the same package under a dedicated export path: import { useGet, useMutation, usePost, usePut, usePatch, useDelete } from 'api-flow-client/hooks'. This keeps them tree-shaken from non-React environments like pure Node.js services or Vue applications.

How can I contribute or report a bug?

Visit the official GitHub repository at github.com/imtiaz-dev-0/api-flow. Open an issue or pull request. Contributions, bug reports, and feedback are always welcome!
